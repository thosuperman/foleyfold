# Feasibility spike
Before building the editor, installed the official Firebase JS web SDK, type-checked the hybrid adapter and ran policy/output-boundary tests. The adapter imports and calls the real SDK, not a locally generated substitute. The sample film, foley and seed cue are original authored fixtures; they are not AI output.

[Firebase web start](https://firebase.google.com/docs/ai-logic/hybrid/web/get-started), [configuration](https://firebase.google.com/docs/ai-logic/hybrid/web/configuration-options), [Chrome Prompt API / hardware](https://developer.chrome.com/docs/ai/prompt-api), [App Check](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider), [Android](https://firebase.google.com/docs/ai-logic/hybrid/android/get-started), [Apple](https://firebase.google.com/docs/ai-logic/hybrid/ios/get-started).

The documented web floor is Chrome desktop 139 and SDK 12.5.0; Prompt API availability depends on Chrome build, enabled features, system resources and language. Desktop Windows 10/11, macOS 13+, Linux or Chromebook Plus; Chrome documents ≥22 GB free and either >4 GB VRAM or ≥16 GB RAM with ≥4 CPU cores. No mobile-web Nano claim. Android native uses Nano; iOS native uses Apple's Foundation Models on supported Apple Intelligence devices. Neither native SDK is in this build.

Only single-turn text is needed. Do not send raw video/audio: web on-device generation is not an audio captioning model. Probe LanguageModel.availability without downloading; check the actual SDK response for provenance. Connect a real project and App Check before invoking. A user gesture initializes the model and may download it. Cloud access requires internet, API enablement and an attested client. Editing/export have no Firebase dependency. Live model execution is unverified here: no authorized Firebase project or registered web app. No fake config or fabricated verification. See the final readiness matrix for environment evidence.
